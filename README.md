# Football Slip

Weekly NFL moneyline picks for a phone: win chances as percentages, a parlay slip with
fair-payout math, Kalshi price comparison, and a season tracker. Static site plus one JSON
file per week, updated by a GitHub Action.

## Layout

```
index.html            page shell
css/style.css         styles (light + dark, follows the phone; Auto/Light/Dark button in the header)
js/core.js            odds math, tiers, parlay/verdict logic (shared by the app and the script)
js/app.js             the app: Picks, Parlays, Tracker
data/index.json       list of week files
data/2026-week-10.json one file per week
scripts/update.mjs    data script (new | refresh | scores)
scripts/sources.mjs   ESPN, Kalshi and The Odds API fetch + parse
scripts/build.mjs     turns source data into a week file
tests/                node:test suites, with trimmed real API responses in tests/fixtures
.github/workflows/pages.yml  scheduled data updates + GitHub Pages deploy
```

## How the numbers are made

- **Win probability**: moneylines from every US book on The Odds API (or ESPN's DraftKings line
  if no key is set), each converted to implied probability, the book's margin removed by
  normalising both sides to 100%, then averaged across books. If no sportsbook line exists,
  Kalshi's prices are normalised the same way.
- **Pick**: the team above 50%. **Tier**: Lock 72%+, Lean 60–71%, Coin flip under 60%.
- **Kalshi**: the current "Yes" buy price for each team, shown as a percentage. When Kalshi sells
  a team for more than 2 points below the estimate, the game gets a "Kalshi value" tag.
- **Suggested parlays**: Safest = three biggest favorites, Medium = five biggest favorites,
  Long shot = the two likeliest underdogs. Only games not yet started.
- **Slip**: chance all legs hit = product of the leg probabilities; fair payout = stake ÷ chance.
  With an offered payout: break-even = stake ÷ payout; good/fair/poor at ±2 points.
- **Notes**: records, last week's results and the Kalshi comparison, generated by the script.
  Edit `note` in the week file to write your own.
- **Results**: derived from final scores. Games already underway when picks were generated have
  no pick and don't count in the record.

## What's on each tab

- **Picks**: tap who you think wins (your pick, saved on this phone, locks at kickoff) next to
  Claude's pick and win chance. Each game shows the Kalshi comparison, the spread, total and
  American moneylines from ESPN's sportsbook feed, weather and stadium, a note, and an optional
  scouting report. The week menu also lists look-ahead "preview" weeks from the schedule file.
- **Parlays**: your slip, "Add your picks", suggested parlays with a progress bar, and the bets
  you placed (a gold card with confetti when one hits).
- **Props**: the week's player-prop parlays, shown with American odds.
- **Tracker**: your record vs Claude's, Claude by tier, by week, net on your bets, and backup.
- A live score ticker runs across the top (straight from ESPN in the browser).

### Hand-written data in a week file

The script keeps these when it refreshes a week; add them by editing the JSON (or ask Claude):

```jsonc
// on a game: scouting report, a string or a list per side
"news": { "KC": { "s": ["Top-5 pass rush"], "w": "Thin at corner" }, "ATL": { "s": "...", "w": "..." } }

// on the week: player-prop parlays; the first is the featured top pick.
// result is null until graded, then "hit" or "miss"; progress (0-1) optionally fills the bar while live.
"props": [
  { "name": "Sunday stars", "tag": "Top pick", "note": "...",
    "legs": [ { "game": "w11-ari-kc", "team": "KC", "player": "Travis Kelce", "bet": "Over 49.5 rec yds",
                "odds": -115, "why": "...", "result": null } ] }
]
```

The script does not fetch prop lines or grade props; those are entered by hand.

## Placed bets

Save a bet from the slip ("Save as placed bet", using stake as cost and the offered payout),
or use "+ Log a bet" on the Parlays tab: name, where (Kalshi by default), cost, payout, and
any mix of team legs and player-prop legs, including games already started. Mark prop legs
Hit or Miss on the bet card once the game ends. Bets and your picks are stored in this browser
on this phone (localStorage). Use Tracker → Export for a backup file and Import to restore it
on another device. Bets can also be put
in a week file's `tickets` array; the script keeps those when it refreshes a week.

## Data script

Needs Node 20+ and no packages.

```bash
npm run week                 # build the week after the newest file; also finalizes last week's scores
node scripts/update.mjs new --week 12
npm run refresh              # re-price the newest week's games not yet started (keeps started games and bets)
npm run scores               # update live/final scores for the newest two weeks
npm test
npm run serve                # http://localhost:8080
```

Set `ODDS_API_KEY` to use The Odds API (free key at the-odds-api.com, about 1 request per run).
Behind a proxy, run Node with `NODE_USE_ENV_PROXY=1`.

## Hosting (GitHub Pages)

One-time setup in the repo on github.com:

1. **Settings → Pages → Build and deployment → Source: GitHub Actions.**
2. **Settings → Secrets and variables → Actions → New repository secret**:
   name `ODDS_API_KEY`, value your key. Optional; without it the ESPN line is used.

The workflow then:

- deploys on every push to `main`;
- builds next week's file every **Wednesday 7:17 AM PT**;
- updates scores hourly during Thursday, Sunday and Monday games, plus a daily catch-up;
- can be run by hand from **Actions → Update data and deploy → Run workflow**
  (`scores`, `new`, `refresh` or `deploy`).

Times are in UTC in the workflow file and assume Pacific Standard Time (the NFL season).

## Limits

- Regular season only (weeks 1–18).
- ESPN's scoreboard API is unofficial and can change without notice; the parsers are covered by
  tests against saved responses so breakage shows up as a failing run.
- Probabilities are estimates, not guarantees.
